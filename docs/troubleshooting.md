# Troubleshooting

Start with `specromancy doctor` and `specromancy status RUN_ID --format json`. Errors use stable process codes documented in the [CLI reference](cli.md).

| Symptom | Cause and recovery |
| --- | --- |
| `specromancy` is missing | Activate the environment where the wheel was installed, or run `python -m specromancy`. Confirm Python is 3.11+. |
| Repository cannot be discovered | Run inside a Git worktree containing `AGENTS.md` and `.agents/skills`, or pass `--repo PATH`. |
| `doctor` reports missing contracts | Reinstall from a complete wheel; do not copy individual Python modules. |
| Canonical skill validation fails | Restore the named `.agents/skills/<name>/SKILL.md`, its frontmatter, and confined relative references. |
| Adapter generation reports a collision | Move or reconcile the user-authored file. Use `--force` only when replacement and backup are intended. |
| Adapter check reports drift | Regenerate after reviewing canonical changes. Do not hand-edit a generated adapter. |
| Adapter cleanup refuses a file | The generated bytes were modified. Preserve or reconcile the file manually; cleanup intentionally will not delete it. |
| Transition is invalid | Run `status` and `next`; invoke only the action allowed by the persisted state. |
| Approval is required or stale | Verify the plan, then run `approve ... --by IDENTITY`. If the plan changed, revoke/replan and record a fresh approval. |
| Artifact validation fails | Open the canonical `artifact path`, restore required headings/tables and IDs, remove placeholders, then run `validate`. Do not patch `run.json`. |
| Artifact digest differs | Restore the accepted artifact or return through its owning phase. Do not update digest fields manually. |
| Lock conflict | Use `lock inspect`. If the owner is active, wait. Recover only a demonstrably stale lock with `lock recover`. |
| Verification command failed | Fix the implementation and record a new blocking command. Use nonblocking only for genuinely optional evidence and supply a durable reason. |
| Repair cycles are exhausted | The run is blocked. Start a new or revised run after changing scope or evidence; do not bypass the bound. |
| Review cannot be independent | Record the limitation honestly. A fresh evidence review is still required; do not claim process or identity isolation that the harness cannot provide. |

Safe cancellation is always available for a nonterminal run:

```bash
specromancy cancel RUN_ID --reason "Explain why work stopped"
```

Cancellation preserves source changes and the full run record. It is not rollback.
