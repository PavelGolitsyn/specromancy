# Release documentation example

- Use the installed engine and the action packet's canonical skill and inputs.
- Base release claims only on the supplied request; do not invent changes.
- Both phases are read-only for project files. Write only the current visit's
  designated run output, then invoke its validation command.
- Never edit `run.json`, `events.jsonl`, the request, or completed outputs.
- Do not publish, stage, commit, or copy notes into project release documents.
  A user may explicitly copy an approved result after the run completes.
